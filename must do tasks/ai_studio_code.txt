## 2. PHASE 0: REPOSITORY INGESTION & SCHEMA DISCOVERY
Before executing any external web searches or modifying data files, you must perform a complete repository audit:
1. **Clone & Inspect:** Read the full directory tree and source files of `https://github.com/AH64-dll/merchant-intelligence`.
2. **Schema Extraction:** Identify the exact data storage format (e.g., JSON, JSONL, CSV, SQLite, Prisma, TypeScript/Python schemas) and document the exact schema governing:
   - Merchant profiles (IDs, names, domains, categories, regions, metadata).
   - Evidence / Sources / Reviews (URLs, platform tags, sentiment, ratings, author/date metadata, verbatim quotes or summaries).
3. **Domain & Scope Analysis:** Understand the target geography, market niche, and merchant types currently represented in the repository.
4. **Baseline Audit:** Run an initial script to measure:
   - `TOTAL_EXISTING_MERCHANTS`: Total merchants currently stored in the repo.
   - `UNDER_EVIDENCED_MERCHANTS`: Existing merchants that have fewer sources than `MIN_SOURCES_PER_MERCHANT` or fail schema validation.

## 3. DATA QUOTA & OMNICHANNEL OSINT STANDARDS
A single merchant record is considered **VALID & COMPLETE** only when it satisfies all of the following criteria:

1. **Minimum Evidence Quota (`MIN_SOURCES_PER_MERCHANT`):**
   - Target: **5 to 10 distinct, verifiable evidence items/reviews per merchant**.
   - Hard Floor: At least **3 distinct, verifiable sources** across different platforms for smaller/niche merchants.
2. **Cross-Platform Social Media & Web Coverage:**
   You must gather real customer opinions, complaints, reviews, and discussions from all accessible platforms:
   - **Reddit:** Subreddit discussions, user reviews, complaint threads, buyer warnings.
   - **Facebook:** Public pages, community consumer groups, public posts, and review threads.
   - **X (Twitter):** Customer mentions, support complaints, threads, and brand sentiment.
   - **Video & Visual Platforms:** YouTube review videos/comments, TikTok buyer experiences, Instagram comments.
   - **Review Aggregators & Consumer Boards:** Trustpilot, Google Maps/Reviews, Sitejabber, ScamAdviser, BBB, and regional consumer forums.
3. **Data Integrity & Zero-Hallucination Policy:**
   - Every evidence entry MUST conform 100% to the repository's native schema.
   - Every source MUST come from a real search result with an authentic URL/permalink, platform identifier, and genuine user sentiment/opinion.
   - **STRICTLY PROHIBITED:** Fabricated URLs, `example.com`, `TODO`, `N/A`, `placeholder`, synthetic reviews, or duplicated boilerplate text across merchants.

Your first operational priority is completing the existing merchants in the repository. **Do NOT add any new merchants until Phase 1 is 100% complete.**

```text
WHILE (existing_merchants_below_quota > 0 OR existing_schema_errors > 0):
    1. SELECT the next batch (10–20 records) of existing merchants that lack sufficient evidence or fail schema rules.

    3. EXTRACT & MAP the findings strictly into the repository's schema.
    4. SAVE & CHECKPOINT the updated batch to disk so progress is preserved.

```
*Phase 1 Gate:* Proceed to Phase 2 ONLY when `existing_merchants_below_quota == 0` and `existing_schema_errors == 0`.
